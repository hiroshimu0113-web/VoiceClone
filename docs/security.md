# セキュリティ・機密情報の扱い

方針: **GitHub には機密情報の「値」を置かない。** 置き場所の約束事だけを書く。

## 情報ごとの保管場所
| 情報 | 保管場所 | リポジトリ内での扱い |
|---|---|---|
| APIキー・トークン(CI/自動処理用) | GitHub Secrets(Settings → Secrets and variables → Actions)。重要なものは Environment secrets + 承認必須 | 値は書かない。ワークフローは `${{ secrets.NAME }}` で参照 |
| ローカル用のキー | `.env`、OSのキーチェーン、パスワードマネージャー | `.env` は `.gitignore` 済み。`.env.example` に変数名のみ |
| 個人情報・同意書 | 暗号化された非公開ストレージ(アクセス者を限定) | 保管場所の名称と管理者のみ記載。本文は置かない |
| 元の音声データ | 暗号化した外部ストレージ / 外部ドライブ | 音声は `.gitignore` 済み。メタ情報(長さ・書き起こし等)のみ `data/` に置いてよい。個人が特定できる内容は含めない |
| 学習済みモデル重み | 外部ストレージ(必要なら Git LFS) | 入手方法・保管場所を `docs/` に記載 |

保管場所の実体(サービス名・フォルダ名・管理者)は、決まり次第この表の下に追記する。

## 事故防止の設定(リポジトリ管理者が実施)
Settings で次を有効にする。
1. Code security → **Secret scanning** と **Push protection**: ON
2. Branches → `main` のブランチ保護: PR 必須、(可能なら)承認 1 件以上
3. Dependabot alerts / security updates: ON(Dependabot 設定は導入済み)
4. Actions secrets に必要なキーのみ登録し、使わなくなったら削除

## エージェント向けルール
- キー・個人情報を、ログ・PR本文・Issue・チャット・コード中に出さない(一部だけの表示も不可)。
- 機密らしきものを見つけたら、コミットせずユーザーに報告する。
- コマンド出力に機密が混ざる場合は、マスクしてから共有する。

## 誤ってコミット/公開した場合
1. そのキー・トークンを**直ちに無効化し、再発行**する(履歴の削除より先)。
2. ユーザーに報告する(何が・いつ・どこに出たか)。
3. 履歴からの除去(git filter-repo 等)は、管理者が必要に応じて行う。除去しても、無効化は省略しない。
4. 個人情報の場合は、本人への連絡が必要か管理者が判断する。
